## Executive summary

The engine layers remain the strong part: the layering still holds, the
parser/compiler are careful, and the test suite has doubled since August and
is still meaningful. The project is in good shape overall.

Four things deserve attention before anything else:

1. **A confirmed solver bug** — the shaft solver refuses ordinary stiff shafts
   (N1).
2. **The document migration path is not wired into the app** — the first
   schema-version bump would refuse every existing student document while the
   fixture tests stay green (N2).
3. **A loaded or cloud-delivered catalogue can permanently replace a built-in
   one** (N3).
4. **Large grids blank the page**, and there is still no error boundary (N4,
   O1).

Most of August's P1/P2 editor findings are still open (section O). `AppShell`
has grown from about 850 to about 1,200 lines.

## N. New findings

### N1 — The shaft solver refuses valid stiff shafts — **P1 / S**

`packages/kernel/src/shaft.ts:123` (`solveLinear`).

Reproduced against the built kernel, steel (E = 210 000 N/mm²), 1 kN at
midspan:

| Arrangement | Result |
| --- | --- |
| fixed–fixed, Ø50 × 500 mm | correct: 500 N, ∓62 500 N·mm (= FL/8) |
| fixed–fixed, Ø100 × 200 mm | **"these supports cannot hold the shaft"** |
| fixed–fixed, Ø150 × 150, Ø200 × 100 | same refusal |
| three simple supports, spans down to Ø200 × 100 | correct |
| three simple supports, Ø300 × 60 mm spans | same refusal |

Cause: rows are scaled to their largest entry and then a pivot is rejected
when its absolute value is below `1e-10`. In the deflection and slope rows the
reaction coefficients are flexibilities of order L³/EI, which for a short,
thick shaft are far smaller than the slope/offset entries they share a row
with, so a perfectly well-conditioned statically indeterminate system reads as
singular. Statically determinate arrangements escape because their reactions
are pivoted from the two equilibrium rows.

**Action.** Scale the columns as well as the rows (or non-dimensionalise the
unknowns by EI/L³), and make the rank test relative to the largest pivot seen
rather than absolute. Add `shaft.test.ts` cases for a stiff fixed–fixed shaft
and a stiff three-support shaft, checked against the closed forms.

### N2 — `migrateDocument` is never called by the app — **P1 / S**

`packages/schema/src/migration.ts:101` defines the upgrade entry point, and
`AGENTS.md` makes a migration step mandatory for any non-additive change. But
every load path calls `loadDocument` (`packages/schema/src/io.ts:74`), which
goes straight to the strict `parseDocument`:

- `packages/editor/src/App.tsx:237` (autosave restore), `:600` (cloud
  publication), `:1041` (file open), `:1059` (recent)
- `packages/editor/src/model/hub.ts:406` (workspace)
- `packages/editor/src/viewer/interactiveRuntime.ts:33` (published viewer)
- `packages/editor/src/model/samples.ts:1838`

The only callers of `migrateDocument` are the fixture tests. So on the first
`DOCUMENT_SCHEMA_VERSION` bump, a correct migration step with a passing
fixture would ship, and the app would still refuse every existing document —
autosaves, recents, files and Hub workspaces alike. The specific "made with a
newer version of JoveWorks" refusal is unreachable today for the same reason.

**Action.** Make `loadDocument` call `migrateDocument(readJsonText(text))`, so
there is one entry point and it migrates. Add a test that goes through
`loadDocument` with a synthetic older version, so the wiring itself is
covered.

### N3 — A loaded catalogue can permanently replace a built-in one — **P1 / M**

`withCatalogue` (`packages/editor/src/model/catalogues.ts:158`) adds or
replaces by id, with no protection for the built-in ids — the
`PERMANENT_CATALOGUE_IDS` set only guards *removal*. Every load path then
caches the result (`cacheCatalogue`), and `initialCatalogues`
(`packages/editor/src/App.tsx:180`) layers the cache over
`builtInCatalogues()` with the same function on every start.

Consequences:

- A catalogue file whose id equals Base, Array or Shafts replaces that library
  in this browser until site data is cleared.
- With cloud enabled, a `?hub=<any https origin>&publication=<id>` link is
  enough: `openCloudPublication` loads and caches whatever catalogues that
  origin returns, with no confirmation. `hubUrl()` requires HTTPS but accepts
  any host.
- `resolveCloudCatalogues` (`model/hub.ts`) checks an inline entry's
  *wrapper* id/version/hash against its ref but never checks the id inside
  `content`, so the catalogue actually loaded need not be the one named.
- Independently of any attacker: a cached older copy of a *bundled* catalogue
  (one a Hub also serves, or one loaded from a file) shadows the newer bundled
  version after the app updates.

Expressions are sandboxed, so this is silently wrong arithmetic, not code
execution — but silently wrong arithmetic is the failure this project is built
to prevent.

**Action.** Refuse (with a notice) any loaded catalogue whose id is a built-in
or bundled id; skip such entries when reading the cache; check
`content.id === ref.id` after parsing in `resolveCloudCatalogues`. Decide
whether a linked publication from an origin the student has not connected to
should ask before loading catalogues.

### N4 — Large grids blank the page — **P1 / M**

Three facts combine:

1. `Math.min(...data)` / `Math.max(...data)` are spread over per-cell arrays.
   In V8 the spread throws `RangeError: Maximum call stack size exceeded`
   somewhere between 100 000 and 130 000 elements (measured in Node; other
   engines have other limits, some lower). Sites over per-cell data:
   - `packages/kernel/src/statistics.ts:59-60`
   - `packages/kernel/src/evaluate.ts:3351` (Best Design)
   - `packages/kernel/src/distribution.ts:32-33`
   - `packages/editor/src/model/values.ts:54`
   - `packages/editor/src/model/plot.ts:243`, `:410`
   - `packages/editor/src/present/PlotFigure.tsx:344-347`, `:375-376`
   - `packages/editor/src/present/IntelligentPlotFigure.tsx:68`, `:289-292`,
     `:308-309`
   - `packages/editor/src/canvas/Sparkline.tsx:54-55`
   - `packages/editor/src/canvas/MonteCarloReceiverPlayback.tsx:109-110`
2. `analyse()` rethrows anything that is not a `KernelError`
   (`packages/editor/src/model/analysis.tsx`, both retry loops), and the
   figure components have no guard of their own.
3. There is no React error boundary (O1).

A 400 × 400 contour (160 000 cells) is enough. `LARGE_GRID` only warns, at
10 000.

Related: nothing caps `points` or `count` at all —
`packages/schema/src/value.ts:272` enforces a minimum of 2 and no maximum, so
a typo of a few extra digits allocates the array synchronously on the
keystroke.

**Action.** One `extent(values)` helper (a loop) in the kernel, exported and
used at every site above. Add the error boundary (O1). Decide a hard ceiling
on total grid cells and refuse above it with a `KernelError`, so an oversized
study is a message on the node rather than a frozen tab.

### N5 — Jupyter export can emit code from a label — **P2 / S**

`comment()` in `packages/editor/src/model/jupyter.ts:504` splits on `\r?\n`
and prefixes each line with `# `. Python also ends a physical line at a bare
`\r` (confirmed: a file containing `# title\rprint(...)` runs the `print`).
`readString` accepts any string for a node label, and `titleOf` falls back to
a catalogue formula's citation, so a crafted document or catalogue with a lone
carriage return in a label puts executable code into the exported `.py` or
notebook.

The generation side was established by reading the code; the exporter was not
run end to end.

**Action.** Split on `/\r\n|\r|\n|\f| | /u` (or strip control
characters first). Add a test with a bare `\r` in a label.

### N6 — A wired Compare threshold pairs by position, not by axis — **P2 / M**

`packages/kernel/src/evaluate.ts:2019` (`evaluateCompare`). A wired threshold
is accepted when its data length is 1 or equals the value's data length, and
is then paired cell for cell. So:

- value swept over `d` (5 points), threshold swept over an unrelated `T`
  (5 points) → silently paired, no error or warning;
- value over `d × T` (25 cells), threshold over `d` (5) → refused, although
  that is the meaningful case.

The docstring calls the length match deliberate. It is nonetheless the one
place in the kernel where two series meet without axis identity deciding how,
and it fails silently.

**Action.** A product decision. The consistent rule is the one everything else
uses: the threshold's axes must be a subset of the value's, and it broadcasts.
If positional pairing is kept, at least refuse when the two carry different
axes of equal length.

### N7 — Reliability pools design axes silently — **P2 / S**

`packages/kernel/src/evaluate.ts:3510`. `reliabilityEstimate` takes
`check.results` whole — every cell. For a check that varies along the trial
axis *and* a design axis, "trials" is designs × trials and the reported
failure probability is an average across designs, which describes no design.
Only `reliabilityNoTrials` is ever warned; the Statistic node warns in the
equivalent situation (`statisticPooledAxes`).

**Action.** At minimum, warn when a referenced check varies along any axis
other than the trial axis. Better: report per design cell, or require the
study to be reduced to one design (a mark) first.

### N8 — Older builds cannot open documents that use newer node kinds — **P2 / S**

`NODE_KINDS` has grown to 22 members under document schema version 1
(`packages/schema/src/document.ts:1775`). `AGENTS.md` promises that "an older
build still opens a newer file" because parsers ignore unknown keys — but an
unknown node *kind*, output kind or enum member is a hard failure at
`readEnum` (`document.ts:1921`), with the message `expected one of 'input',
'range', …, got 'zip'`. With a stable channel hosted by a school and a faster
nightly, that is a student's likely first encounter with a version mismatch.

**Action.** When `kind` is not recognised, fail with the same "made with a
newer version of JoveWorks" wording `migrateDocument` uses. Correct the
sentence in `AGENTS.md` to say what is actually forward-compatible.

### N9 — Kernel function edge cases — **P3 / S**

`packages/kernel/src/functions.ts`, confirmed against the built kernel:

- `at(xs, 5)` on three values returns `undefined` (so does a negative index),
  which then travels as a number. Should be a `KernelError`.
- `CONSTANTS` is checked before the environment (`compile.ts:190`), and
  nothing forbids a port named `pi`: `pi * 2` with a port `pi = 10` evaluates
  to 6.28. Refuse the name when a formula record is checked.
- `sdev` of a single wire is `NaN` with no message.
- `log` is the natural logarithm and there is no `log10`. For a German
  textbook that writes `lg`, that is a transcription hazard worth either a
  `log10`/`lg` entry or a note in the authoring guide.

### N10 — Autosave is one slot shared by every tab — **P3 / S**

`packages/editor/src/io/autosave.ts:10`. Two tabs with different unsaved
documents overwrite each other's snapshot, and opening a file in one tab
clears the other's. Whichever tab closes last decides what "restore" brings
back.

**Action.** Key the slot by document id (and prune old ones), or note the
limitation where the restore notice is shown.

### N11 — Build-flag documentation disagrees with the release workflow — **P3 / S**

`netlify.toml` and `packages/editor/src/cloud/enabled.ts` say a self-hosting
school gets a build with no cloud surface. The stable bundle a school
downloads is built by `.github/workflows/release.yml` with `VITE_CLOUD: hub`.
`enabled.ts` does state both facts, but `netlify.toml`'s comment and
`HOSTING.md`'s framing read as if the zip were cloud-free.

**Action.** Decide which is intended and make the three places agree.

### N12 — `pnpm build` / `pnpm test` do not run non-interactively here — **P3 / S**

The documented validation commands abort in the main checkout because pnpm's
dependency check wants to purge `node_modules`. `AGENTS.md` describes this for
worktrees only. Not diagnosed: `node_modules/.modules.yaml` records a prune on
19 October and the global store, while the lockfile last changed on
23 October and a repo-local `.pnpm-store/` exists.

**Action.** Run `pnpm install` once interactively and see whether it settles;
if it recurs, record the workaround in `AGENTS.md` for the main checkout too.

## What is in good shape

- **The parser and compiler.** No `eval`, no `new Function`; precedence and
  associativity are right (`-2**2`, `2**3**2`, `2^-1` all checked); the
  predicate backtracking is not exponential (24 nested parentheses parse in a
  millisecond); the dimension pass and its handling of unresolved generic
  ports are carefully reasoned.
- **Sampling.** The Monte Carlo generator's "sample *i* never changes as the
  count grows" property is real and follows from the design, not from luck.
- **HTML injection sites.** All five go through KaTeX with its default
  `trust: false`, and the non-math parts are escaped.
- **The Hub client.** Tokens for cloud access stay in memory; catalogue
  responses are pinned by content hash; HTTPS is required.
- **The interpolation and lookup evaluators** refuse a miss rather than carry
  a `NaN` downstream, and say which row and column were asked for.
- **The test suite** doubled since August and still tests behaviour: the
  layering test, the fixture corpus for saved documents, and the kernel's
  edge-case tests are all the kind that catch real regressions.
